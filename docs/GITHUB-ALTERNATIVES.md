# Альтернативные движки и план расширения русской мультстудии

Дата проверки: 2026-11-10

## Текущая база

OpenReels уже закрывает основной конвейер: тема → сценарий и сцены → TTS → изображения/видеоклипы → музыка → субтитры и монтаж → MP4. В текущем API зарегистрированы видео-провайдеры Google Veo и fal.ai. Поэтому замена проекта целиком не даёт очевидного выигрыша. Расширять нужно прежде всего слой видеогенерации и устойчивость персонажей.

## Рекомендуемая архитектура

1. Сохранить OpenReels как orchestration/UI/rendering слой.
2. Добавить отдельный ComfyUI video provider, который отправляет workflow в ComfyUI API, ждёт завершения, скачивает клип и возвращает его в существующий scene pipeline.
3. Вынести workflow JSON в workflows/ и конфигурацию endpoint/model в переменные окружения. Не загружать тяжёлые модели в Git.
4. Добавить capability check/health check и fallback на существующие Veo/fal провайдеры.
5. Для постоянства героев хранить reference image/character sheet и передавать его в workflow для каждой сцены; один только текстовый prompt не гарантирует идентичность.
6. Перед публичным запуском закрыть API авторизацией, ограничить CORS, защитить передачу API keys, добавить лимиты/очередь и HTTPS.

## Почему интеграция не была подменена фиктивной

GitHub connector имеет права чтения внешних репозиториев, но не push в них. Кроме того, Agnes и Short Video Maker — самостоятельные приложения, а не совместимые OpenReels provider-модули. Их прямое копирование добавило бы второй сервер и несовместимые зависимости, не обеспечив реальной интеграции. LTX/ComfyUI — наиболее чистая точка расширения, но для реального запуска нужны доступный ComfyUI endpoint, модельные файлы и подходящая GPU.

## Проверка перед включением любого backend

- лицензия кода и лицензии/условия весов моделей проверены отдельно;
- русский TTS проверен реальным аудио, а не только заявлением README;
- пробная сцена с reference image успешно рендерится;
- итоговый клип проходит через существующий FFmpeg/Remotion монтаж;
- есть таймаут, retry, отмена и очистка временных файлов;
- стоимость/лимиты и политика хранения исходных промптов понятны.
